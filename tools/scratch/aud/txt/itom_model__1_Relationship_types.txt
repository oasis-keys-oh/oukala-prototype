Relationship type catalog
Each type has a label for each direction, an example and the class pairs it is meant for. Types that read naturally the other way (Contains, Provides, Supports) are stored inverted so impact still flows upward.

TYPE	READS FORWARD	READS BACKWARD	MEANING AND EXAMPLE	ALLOWED PAIRS
depends on	Depends on	Used by	The source cannot work without the target. This is the default for impact analysis: if the target fails the source is affected.
Example: Application depends on Database
	Application → Database Service → Service Application service → Application
runs on	Runs on	Runs	Software or a virtual machine that executes on a host, container or platform.
Example: Application runs on Virtual machine
	Software → Computer Software → Cloud Cloud → Computer
hosted on	Hosted on	Hosts	Physical or logical placement: a server in a rack, a virtual machine on a host or subscription.
Example: Server hosted on Rack
	Computer → Rack Network device → Rack Cloud → Cloud subscription
connects to	Connects to	Connected by	Network or data connection between two items that does not imply ownership.
Example: Server connects to Switch
	Computer → Network device Network device → Network device Network device → Cloud
uses	Uses	Used by	Consumes a shared capability such as an identity tenant, API or reference data store.
Example: Application uses Cloud resource
	Software → Configuration item Business application → Information object Service → Configuration item
consumes	Consumes	Consumed by	A service or application takes data or output from another.
Example: Business service consumes Application service
	Service → Service Application → Application

Example: Application runs behind Load balancer
	Configuration item → Network device
