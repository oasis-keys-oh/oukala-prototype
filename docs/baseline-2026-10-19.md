# Baseline measurements, 2026-10-19 (CL-01)

Every number below is a **prototype fact**: measured on this build, on one machine, on the date shown. None is a forecast or a production figure. The later measure (CL-49) reruns the same script so the two can be compared.

## How it was measured
- Build: branch `repo`, commit `f1c7ac9`, `python3 src/build.py --out build_out` (default outputs).
- Script: `node tools/baseline.js build_out --runs 5`. It serves `build_out/` from 127.0.0.1 with `Cache-Control: no-store`, opens `index.html` in a fresh Chromium context for every run (cold cache), and blocks every request that is not to the local server (the Google Fonts stylesheet), so the numbers depend only on the build.
- Machine: Apple M5, Node 22.22.2, Playwright 1.58.2 headless Chromium, viewport 1440 x 900. Local loopback: no network latency or bandwidth limit, so real visitors will see longer fetch times.
- "App ready" means the screen registry exists and `#view` holds more than 400 characters of markup.

## Cold load (prototype fact, median of 5 runs, milliseconds from navigation start)
| Milestone | Median ms | Range over 5 runs |
|---|---|---|
| First byte of `index.html` | 4.4 | 3.0 to 12.6 (local server) |
| `oukala-js.js` fully fetched | 182 | 170 to 188 |
| DOMContentLoaded finished | 2,788 | 2,363 to 2,945 |
| Load event finished | 2,793 | 2,367 to 2,950 |
| App ready (first screen rendered) | 6,631 | 5,903 to 6,998 |
| JS heap in use at ready | 124.9 MB | 104.0 to 141.1 MB |

Reading: fetching is not the cost on loopback; about 2.6 seconds go to parsing and running the 11.9 MB script before DOMContentLoaded, and about 3.8 more seconds of startup work run before the first screen is ready.

## Coverage at first use (prototype fact)
Measured from a cold load through opening the screen, then 0.8 seconds idle. Totals are in characters of source (the JS is 11,843,982 characters; CSS counts every inline stylesheet).

| Screen | JS used | JS used share | CSS used | CSS used share |
|---|---|---|---|---|
| `home` | 4,496,166 of 11,843,982 | 38.0% | 474,454 of 1,550,686 | 30.6% |
| `ppl_jrny` (Experience journeys) | 4,516,522 of 11,843,982 | 38.1% | 492,580 of 1,550,686 | 31.8% |
| `showroom` (Showroom home) | 4,516,906 of 11,843,982 | 38.1% | 477,480 of 1,550,686 | 30.8% |

Reading: about 62% of the JavaScript and 69% of the CSS shipped on first load is not executed or matched on these three screens. The share barely moves between screens because most of the executed code is startup work every module does at load, not screen rendering.
