# Round 8 feedback checklist (Casey, verbatim substance). Each item gets an ID for tracing.
General: R0a use existing tokens and push (internal prototype). R0b scale: hundreds/thousands of projects, CIs, assets. R0c drawers can go full screen. R0d every tab first opens on dashboard + list view. R0e linked records at hundreds => tables/accordions. R0f every metric uses the standard framework (formula, remediation, fchip). R0g text spacing easier to view everywhere. R0h every Incident/Problem/Change/Release attaches a service and a visual impact analysis. R0i leverage standards (ITIL 5, ATUM/TBM, PMP/PMBOK, SAFe, CSDM...). R0j assign to a TEAM first, then person. R0k everything chat controllable, audit every action, AI lineage and guardrails visible.
S1 Screenshot: OKR cards squeezed text / text spacing in multiple places. S2 Milestone drawer: dates and float look off. S3 Approval workflow card (board pack): buttons crowded. S4 Formula chip italic and cramped.
N1 Portfolio and Delivery nav: move invoices and delivery under it; demand and executive trace likewise; executive dashboard to the parent; strategy alignment at top.
W1 Line-by-line WBS per project is the data for each Gantt (MS Project): WBS, tasks/nested tasks, planned vs actual start/end, durations, predecessors, milestones that feed milestones.
O1 SOW analyzer: vendor proposal + final contract stored with T&C; each line (commitment, outcome, measure) line-by-line; AI picks standard terms or recommends new for legal/shared review; manage/request changes (schedule, project, change request, assumptions); pulls all existing data together.
T1 Projects and Teams: human vs AI vs contractor vs MSP. T2 avatars/pictures. T3 click a person => everything assigned (projects, tickets, approvals...). T4 pills do not scale to 20+ projects: dropdown/multi-select.
M1 Strategy alignment: maturity models (ours + ingest others); model, target, how projects inform maturity; one per topic (autonomous service delivery, project traceability). M2 strategic goals => capabilities each measured; 1/3/5 year on-track; charts, models, action items. M3 "we need level 5": impact across child capabilities and platform dependencies.
I1 Incident: assign to team then person (ITIL). I2 industry standards everywhere (ITIL 5, ATUM/TBM, PMP). I3 ATUM/TBM visually depicted for services: usage, spend per service, scale triggers (hire help desk person, add server), AI search/new API licensee growth. I4 Every service mapped 7 ways: technical, business objectives/strategy/maturity, projects (using/impacting/improving/deprecating), stakeholders (service owner, process owner, business users, SMEs), performance measures, financial measures, impact measures. I5 Impact + Urgency = Priority: impact quantitative vs service key metrics; urgency qualitative bounded by level/impact (low-level analyst critical? VIP levels); priority calculated; override roles.
P1 Problem: visual fishbone diagram. P2 linked records hundreds => tables/accordions. P3 drawers full screen.
C1 Changes: spacing between calendar and tiles. C2 impact analysis button/visual (ServiceNow-like). C3 configurable approval processes by service, CI, type, group. C4 explain the purple bar in the sidebar section (legend/descriptors).
R1 Releases: scrum/team mgmt + SAFe terms (sprints, increments, features, release trains, backlogs, burndown). R2 enhancement vs defect; dev status; human vs automated test; exit/acceptance criteria; user stories + point standards; pull requests; release clashes. R3 training done/approved; comms approved; OCM plan implemented: child activities/tasks/standard project approach? R4 person plate: incidents, project activities, meetings, action items, PTO; can they handle more; performance vs baseline/peers.
V1 Service Catalog: complex workflows (laptop: procure, receive, asset inventory, image, prep, accounts, security, Intune/MDM, approvals multi-trigger). V2 each CMDB service has offerings/sub-offerings; request is an offering. V3 data triggers approvals; pending/approved/deployed/decommissioned requests visible on service. V4 infrastructure/scale/financials per service via TBM => scale up/down => auto-add to demand. V5 onboarding workflow with laptop as one part. V6 cost and performance per step; SLA/OLA/XLA per step. V7 customer portal view + admin pages. V8 robust forms (graphics, tabs, accordions, explanations, AI-assisted). V9 requester status "who it is sitting with"; workflow decides what requester sees.
H1 Chat: context aware = page, person, their records, on behalf of someone. H2 available platform-wide, multiple threads and activities (onboard a user, how an SLA is measured, raise my token limit). H3 answers AND inline fulfillment and agentic actions (Flow/Moveworks).
L1 SLAs/OLAs: add XLAs. L2 define with real fields/data across the platform. L3 define when active and when it turns off. L4 SLA coverage by process. L5 each tab shows its interconnected processes/workflows visibly, admin can adjust.
G1 On Call: ROTA per team/service/asset. G2 coverage map views, daily/weekly/hourly. G3 system recommends coverage times. G4 automated assignment by team/skills/availability. G5 skills database.
Q1 Self-service portal more visually appealing; different forms per item (laptop, phone, new project) with guidance, pictures, process, approvals, costs.
D1 CMDB works at hundreds/thousands CIs. D2 CI impact analysis (ServiceNow-like). D3 ingest from SolarWinds and others for uptime. D4 robust CMDB data model, classes and attributes per class (ServiceNow CMDB, CSDM).
E1 Event mgmt: charts/dashboards like SolarWinds/Nagios; thresholds, duplicate alerts, false positives, patterns. E2 deterministic or agentic workflows on alert (checks, restart, increase storage) with pre-approved standard changes; standard change catalog with SOPs; runbooks merge. E3 replace all of a mid-size business's observability tools.
X1 DevOps: merge ITSM change/release, projects, DevOps into one integrated process; natural part of pipeline. X2 master process flow of the whole system + master data model view.
K1 Knowledge: how does it become source, output, automated agentic fulfillment. K2 living graph loved; CMDB and other dot-walking graphs need a similar view.
Z1 Org chart: add performance management. Z2 Resource planning scales across all work types (projects, incidents, requests, operational work, meetings, PTO). Z3 Journey maps: become integrated workflows? agentic fulfillment per box? one/many processes per box?
F1 Workflow designer: how to tell a step to do something: conditions, parameters, inputs/outputs, human/agentic/deterministic; decision tables. F2 Approvals inbox: any permitted user can approve (budget line, contract term, SLA, service change, security assessment). F3 assessments separate from approvals; required gates or advisory input approver can override.
Y1 Visualization builder: a LOT more visualizations (charts, graphs, maps for geographic coverage and incidents, shape/image-based charts like car sales shaped like a car, other types).
Standing earlier asks (round 6/7): demand drag and drop; intake; score hover; fund-to-project; contract ingestion; schedule filters by project; PM/individual assignment; milestone progress; RAID; Obsidian-style knowledge graph; ITSM components; budgets; executive views; features with forms.
