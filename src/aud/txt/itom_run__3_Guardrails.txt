Global guardrails
These apply to every automation rule. A guardrail never lets an AI agent change something that a human could not have pre-approved.
Kill switch
Stops all automation immediately. Alerts keep flowing to people.
Only pre-approved standard changes
An automation rule can run only a catalog entry whose pre-approval is current. Anything else becomes a normal change for the CAB.
Human approval when risk is high
High-risk entries always need an approver. Medium risk needs one unless the rule is explicitly set to allow autonomy.
Blast radius
Each rule caps how many CIs one run can touch, and the catalog entry has its own cap. The smaller wins.
Rate limit
A rule can run a limited number of times per hour, so a flapping alert cannot restart a service in a loop.
Rollback
Every entry needs a rollback. If validation fails after the change, the rollback steps run and the change is closed as failed.
Freeze and error budget
Changes are held during a freeze, and risky ones need approval when the service has spent its error budget.
Audit
Every decision, approval and step is logged with who or which agent did it.
