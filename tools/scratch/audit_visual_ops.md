# Visual / UX / UI audit: OPS, AUTOMATE, PEOPLE, KNOWLEDGE, PLATFORM

Build: review_build/full.html (Oukala, 91 screens). Reviewed 2026-10-07 at 1440 light (full page, every screen in scope), 1440 dark, 1000 and 400 phone (metrics and screenshots for every screen), SCALE-on spot checks, and the tabs of ppl_org, ppl_perf, ppl_cap, ppl_jrny, plat_data, kcs_viz, vault, flw_design editor. Global chat dock tested on 5 screens (home, itom_cmdb, kcs_home, adm_gate, ppl_org). All screenshots are in `vo/shots/` (relative to this file). Source was not edited.

Method notes. Screens that lazy render below the fold (kcs_viz silhouettes, linked visuals) look blank in full-page captures; I re-shot them by scrolling and they render, so only the missing skeleton is logged (VO-044). Phone and 1000 widths had no horizontal page overflow on any screen (good). No page errors or console errors on any screen.

Severity count: blocker 0, major 20, minor 33, polish 6 (59 findings).

## Chat dock verdict (5 screens)

Strengths: the plan card and confirm flow work. Claude-filled tags on fields, "How I got there" steps, a model-and-confidence chip (for example "Claude Sonnet 70%"), RBAC and guardrail chips (G2, G5), a cost and approver summary ("$1,770 hardware, approvals from manager and data owner") and a "Review the plan / Submit order / Open the full form" ladder are exactly the lineage Casey asked for. "how is the SLA measured" returns a clean answer card with the escalation table, two metric sparklines (operational health and mean time to resolve) and an "Open this agreement" action; it needs a bit of bounding (the answer card scrolls internally). The Activities tab (steps with Policy engine = Automatic and Claude = AI agent badges, progress bar, collapsible Guardrails and Parameters) is the clearest part.

Weaknesses (see VO-011 to VO-014): panel size and header height, heavy slab inputs, thread titles stuck on the first ask, scroll position after a long card, translucent on-behalf-of picker, and the context strip changes height between pages (one row on home, 2-3 rows on knowledge pages) which makes the message area jump. The empty state suggestion chips are clipped at the bottom right ("Show m..."). Reduced motion: not verifiable in the screenshots; the stream animation and `rise` entrance should honor `prefers-reduced-motion` (check style4.css).
