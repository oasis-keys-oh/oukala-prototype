Change gate criteria
A change is approved automatically only when every criterion below is met. Two criteria stop the pipeline outright. The rest send the change to the CAB. Pass rate is for production deployments in the last 30 days.

Release gates and where the pipeline checks them
Release records list gates (hard or advisory). The pipeline completes the ones it can check itself, so people only handle what a machine cannot.
RELEASE GATE	TYPE	CHECKED BY	EVIDENCE
Development complete	Hard	Pipeline: Work item, Pull request	Board: every story in the release is Done
Code review done and pull requests merged	Hard	Pipeline: Pull request	Repository: pull requests merged with reviewers
Automated test suite passes (95% or better)	Hard	Pipeline: Test	Pipeline run report
Manual user acceptance testing complete	Hard	A person	UAT sign-off sheet
Exit criteria and acceptance criteria met	Hard	A person	Exit criteria matrix
Security review	Hard	Pipeline: Security scan	Scan report and review record
Change approval (CAB)	Hard	Pipeline: Change gate	Change record approval
Training built	Advisory	A person	Training package in the learning system
Training approved	Advisory	A person	Training approval record
Communications package built	Advisory	A person	Draft announcement, FAQ and release notes

Support handover and monitoring ready	Hard	Pipeline: Verify	Handover note and runbook link

How a change reaches production
Each step is a person, an AI agent, an automatic action or an approval gate. Select a step to see who owns it and how fast it should be. Aligned to DORA metrics, ITIL 5, SAFe.

PERSON
Work item
A backlog item or project task is the start of every change.
PERSON
Commit and pull request
Code is committed with the work item id and reviewed.
AUTOMATIC
Build, test and scan
Compile, run tests, scan for vulnerabilities, sign the artifact.
APPROVAL GATE
Change gate
The gate reads the evidence: standard changes are approved automatically, normal changes go to the CAB, emergency changes to the ECAB.
AI AGENT
Deploy
The release agent deploys in the agreed window and respects freezes.
AI AGENT
Verify
The service level objective is checked for 15 minutes. If the error budget burns, the deploy is rolled back.
AUTOMATIC
Close and learn
Release and change records close with the outcome. DORA numbers update.
